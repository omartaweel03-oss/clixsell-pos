=====================================================================
   نتائج تنفيذ التقارير وتحليل المبيعات - ClixSell POS
=====================================================================

المرجع: التقرير ص 22 (UR-M7، UR-M8)، ص 25 (SR20، SR21)، ص 29 (جدول 3.7)،
ص 36 (الشكل 3.7)، ص 37 (الشكل 3.8)، ص 46 (ERD).
البنية ما تغيّرت: Flutter -> REST API -> Spring Boot -> SQLite (بدون Firebase).


1) اللي نفّذته
---------------------------------------------------------------------
شاشة "المبيعات" (Sales Analytics) - الشكل 3.7:
  - اختيار الشهر والسنة، وأي تغيير بيعيد تحميل الأرقام.
  - رسم خطي للمبيعات اليومية للشهر (كل يوم، والأيام بدون مبيعات = 0).
  - رسم أعمدة للمبيعات الشهرية للسنة (12 شهر، والشهر المختار مميّز).
  - رسم دائري (donut) لأكثر المنتجات مبيعاً مع النسب.
  - قائمة "الأصناف التي أوشكت على النفاد" مع الصورة (أو أيقونة إذا ما في
    صورة)، وعلامة ⚠ للمنخفض و ⊗ للنافد.

شاشة "التقارير" (Reports) - الشكل 3.8:
  - 4 بطاقات:
      إجمالي المبيعات (صافي، مع النسبة مقارنة بالشهر الماضي)
      إجمالي القيمة (قيمة المخزون الحالية)
      عدد الفواتير (مع النسبة مقارنة بالشهر الماضي)
      إجمالي الأرباح = "غير متاح" (السبب تحت)
  - اختيار "الشهر المحدد" أو "السنة كاملة".
  - زر "توليد تقرير": بيعرض التقرير كامل كنص، مع زر نسخ.
  - رسم المبيعات اليومية (أو الشهرية إذا اخترت السنة كاملة).
  - "المنتجات المميزة": الصورة، الاسم، عدد المباع، والقيمة بالشيكل.
  - "تقرير المخزون" (UR-M8 / SR21): عدد المنتجات، الوحدات، قيمة المخزون،
    متوفر/منخفض/نافد، وجدول حسب التصنيف.

القائمة الجانبية: انضاف قسم "التقارير" فيه "التقارير" و"المبيعات"،
لمدير المتجر بس. الكاشير ما بيشوفهم.
الشاشتين بتدعموا العربي (RTL) والموبايل.


2) الـ API الجديد (لمدير المتجر بس)
---------------------------------------------------------------------
  GET /api/reports/summary?from=&to=          البطاقات + المقارنة بالفترة السابقة
  GET /api/reports/daily-sales?from=&to=      نقطة لكل يوم
  GET /api/reports/monthly-sales?year=        12 شهر
  GET /api/reports/top-products?from=&to=&limit=   أكثر المنتجات مبيعاً
  GET /api/reports/inventory                  تقرير المخزون + المنتجات للطلب
- المتجر بيتحدد دائماً من المستخدم المسجّل دخوله. أي storeId بالطلب بيتجاهل.
- الكاشير والـ System Admin: 403. بدون تسجيل دخول: 401.
- استخدمت من جديد: ProductService و Product.getStockStatus (قواعد المخزون
  الموجودة)، والجداول الموجودة (sales، sale_items، returns، products).


3) كيف بتنحسب الأرقام (بالـ backend، مش بالتطبيق)
---------------------------------------------------------------------
- بتنحسب الفواتير المكتملة (COMPLETED) بس. المعلّقة والملغاة ما بتنحسب أبداً.
- تاريخ الفاتورة = وقت إتمامها، والفترة أيام كاملة.
- المبيعات = المبلغ اللي دفعه الزبون (بعد الخصم، شامل الضريبة).
- صافي المبيعات = المبيعات - المبالغ المرتجعة بتاريخ المرتجع.
- أكثر المنتجات مبيعاً: الكمية = المباع - المرتجع. القيمة = حصة المنتج من
  المدفوع، بنفس قاعدة حساب المرتجع الموجودة.
- "أوشكت على النفاد": نفس قواعد المخزون الموجودة (نافد = 0،
  منخفض = الكمية <= الحد الأدنى). ما اخترعت أي حد جديد.
- الشهر بيتقارن بالشهر اللي قبله، والسنة بالسنة اللي قبلها.


4) الربح - قرار بحاجة موافقتك (ما غيّرت قاعدة البيانات)
---------------------------------------------------------------------
1. هل في تكلفة للمنتج؟ لا. جدول products ما فيه cost_price، مع إنه موجود
   في الـ ERD (ص 46).
2. هل بنقدر نعرف تكلفة المبيعات القديمة؟ لا. ما في أي تكلفة محفوظة، فالربح
   القديم ما بينحسب بدقة.
3. الحقول المقترحة:
   - products.cost_price (سعر الشراء، اختياري).
   - sale_items.unit_cost (نسخة من التكلفة وقت البيع، "snapshot").
4. طريقة الحساب المقترحة:
     الربح = (صافي المبيعات بدون الضريبة) - (تكلفة الوحدات المباعة)
   - الضريبة مش ربح، لأنها بتروح للدولة.
   - الخصم بينقص من المبيعات.
   - المرتجع بينقص المبيعات وبينقص التكلفة كمان.
5. هل الـ snapshot ضروري؟ نعم. لو تغيّر سعر التكلفة بعدين، الأرباح القديمة
   ما بتتغيّر.
6. أمان البيانات: migration جديد (V4) بيضيف أعمدة بس، فاضية (NULL)، وما
   بيغيّر ولا بيحذف أي سجل. المبيعات القديمة بتضل بدون تكلفة، وبتنعرض
   "غير معروف" بدل رقم مزيّف. والربح بيظهر بس للمبيعات اللي إلها تكلفة.
   والمدير بيدخل سعر التكلفة من شاشة المنتج.

لحد ما توافق: بطاقة الربح مكتوب عليها "غير متاح - يحتاج سعر تكلفة
المنتجات"، والـ API بيرجع profit.available = false بدون أي رقم.


5) الاختبارات
---------------------------------------------------------------------
- Backend: 90 اختبار، كلها نجحت (كانت 77). الجديد: 13 اختبار API للتقارير:
    متجرين، المكتمل مقابل المعلّق والملغي، المرتجعات، حدود الأيام، الشهر
    والسنة، أكثر المنتجات مبيعاً، المنتج المحذوف، المخزون، الصلاحيات (401/403)،
    الفترات الغلط (400)، ومتجر بدون مبيعات.
    كل رقم محسوب باليد ومكتوب بالاختبار.
- Flutter: 81 اختبار، كلها نجحت (كانت 70). الجديد: 11 اختبار للشاشتين:
    التحميل، القائمة، الفلاتر، قيم الرسومات، الخطأ وإعادة المحاولة، العربي
    RTL، و3 أحجام شاشة بدون overflow.
- flutter analyze: بدون أي ملاحظة.
- فحص حقيقي (سيرفر + قاعدة بيانات حقيقية + متصفح) لمتجرين:
    كل الأرقام طابقت حساب SQL مستقل (المبيعات، المرتجعات، الصافي، الفواتير،
    المخزون، مجموع الأيام).
    الكاشير 403، وما في ولا منتج مشترك بين تقارير المتجرين.
- الوظائف القديمة (الدخول، المنتجات، POS، الفواتير، المرتجعات، تعدد
  المتاجر) كل اختباراتها لسا ناجحة.


6) الناقص
---------------------------------------------------------------------
- الربح: بحاجة موافقتك على الـ migration (قسم 4).
- صور المنتجات بتظهر بس إذا المنتج إله صورة (بالبيانات التجريبية ما في صور،
  فبتظهر أيقونة).
- "توليد تقرير" بيعرض نص قابل للنسخ. ما في PDF ولا طباعة، لأن التقرير ما
  حدّد صيغة.
- بطاقة "إجمالي القيمة" بالشكل 3.8 مش واضحة بالتقرير، ففسّرتها كقيمة المخزون
  (SR21). إذا قصدك شي ثاني، خبّرني.
